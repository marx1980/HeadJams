# UI Layout Rules

- Keep File, Settings, Help, and other header controls on the left; keep Play/Stop at the right end of the header row.
- Render the MusicMaker wordmark in white.
- Keep the Sound library's Search sounds and Tag controls the same height when displayed in the same row.
- Keep every control in the Beat tab's options row (Template, BPM, Note length, Loop, Pattern, Drum kit, Apply kit) the same height and font size; they share `--option-control-height` in `.beat-options`.
- Select dropdowns use `appearance: none` with a CSS chevron; iOS Safari ignores `height`/`min-height` on native-styled selects, so never remove it.
- In each channel strip, align controls to the bottom edge and keep every control 40px tall so Track name and the sound picker line up.
- Channel strip order is: Track name, then [sound picker, S (solo), M (mute), preview], then Volume/Pan, then [duplicate, Piano roll/Grid, remove]. On phones each group is its own row (picker takes the remaining width), so nothing can wrap alone.
- Library: Sounds, Find the sound, Sample editor and Ideas (with Recognition) are exclusive accordion sections (`<details name="library-section">`); search/tag/channel filters live inside Sounds. Sound tiles stay two columns, with Play above Use on the right, no inner scroll, grouped by category as an exclusive accordion: every group starts collapsed, opening one collapses the previous, and a search or tag filter opens the first matching group. Tutorials open any collapsed section that contains their target.
- Library, Song and Sound controls are 40px and arranged in two-column grids (`.record-controls`, `.recognition-controls`, `.effect-controls`); a select and its action button share a row and stack full width when they do not fit.
- Do not add explanatory paragraphs to the Library, Song or Sound tabs; labels and values only.
- Sound tab: the top tile is "Shape a sound" (swing and effects) and the bottom tile "Make a sound" (the designer) is always shown, with no toggle button or Close.
- Status toasts sit above the sticky header (z-index 30) at the top right; the first-visit "New here?" bubble sits above the bottom tab bar so the two never overlap.
- Undo/Redo live at the top of the File tile (the header has no room at 320–390px); big one-shot actions add an Undo button to their toast.
- Header row: File, Settings, Help, then a red Capture (record) button, with Play at the right end. At ≤380px Play narrows to fit; the row must fit at 320px.
- Library's third section is **Ideas**: one 40px row per captured take (name, Hear as select, play, delete) as a four-column grid, then a Start row (label, ←, value, →) when the take has tracks; above the advanced recognition controls; at ≤380px the select narrows to 104px so the name stays readable at 320px.
- Song › Chords by ear: Mood, Key, Rhythm and Play on selects, the Chord names checkbox and Find chords follow the 40px two-column control grid (chord names hidden leaves only the progression name); each progression is one row (name and chords on the left, wrapping under the name when narrow; 44px Play and 64px Use on the right).
- Beat › piano roll › Chord row (guitar chord channels): Chords input full width, then Pattern/Strum and Humanise/Capo in a two-column 40px grid (four columns from 700px), then Apply (fills the row), Advanced and remove; chord shapes list below when Advanced is on.
- Kit channels (one channel, the whole kit as lanes): the strip shows a kit select in the sound picker's place and no Piano roll button; lanes show Kick, Snare, Closed hat (and any lane with hits), each with its name above a normal 40px beat grid; "All lanes · N" reveals the rest.
- Capture sheet (idle): Part and Into side by side, then Bar (only when the loop has several bars) beside Metronome (Metronome is full width without Bar), a Headphones cue when the project already makes sound, the big Record button, then Chords and Harmony side by side.
- Capture › Tap rhythm: one large pad (≥160px) while tapping, then a step strip, Use for / Into side by side, and Again / Use. Draw melody: a full-width 220px pad, Original/Cleaned/Tight in thirds, the note stepper row (← n/N → Lower Higher), then clear, play and a wide Use.
- Song › Song builder: Template + Sections in the control grid; one 40px row per section (name, pattern select only when there are several patterns, −, size, +, remove), then add / play / wide Use.
- Library › Find the sound: Track select full width, description words as 40px toggle buttons in an auto-fill grid (two per row at 320px), then result rows (name over matched words; 44px Play, 64px Use showing a check when it is the track's sound).
- Library › Sample editor › Make an instrument: one 40px row per saved sample (checkbox + name, then a 96px note select once ticked), Name input, full-width Make instrument.
- Beat › Tracks | Bars: a two-button toggle (max 320px wide) under the options row. Each bar card: 40px family letter + name input, a 64px sketch, then one row of 40px controls (Loop, ←, →, Duplicate, More select filling the rest — Copy to and Vary groups — and Clear); at ≤380px the gap is 4px so More stays readable at 320px. Cards are one column, two from 700px; Double loop below.
- Settings › Offline: a full-width Install app button only when the browser offers it, then one row, "Instruments n/N" on the left and a 120px Download all button (shows files done/total while downloading, Downloaded when complete).
- File › Share: a full-width Share link button, then the link in a read-only field once made. Song (opened from a link): name, "BPM · tracks", then 44px Play and a wide Open.
- File › Export: after Export WAV, a two-column row: Video select (Vertical, Square) and Export video ("Recording n/N s" while recording). Video frames carry the song name and one label at the bottom (Hummed, the section, or BPM) only.
